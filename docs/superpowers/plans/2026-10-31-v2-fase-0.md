# Rediseño v2, fase 0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Inventariar el juego real y preparar contratos de datos verificables para el rediseño, sin sustituir todavía las ediciones jugables.

**Architecture:** Conservar JavaScript, Canvas y la distribución en HTML autocontenido. Incorporar JSON Schema 2020-12 para los datos futuros y un extractor reproducible del motor legado. La v2 es la especificación de producto; esta entrega corresponde exclusivamente a su fase 0.

**Tech Stack:** JavaScript/Node.js, Python 3 y jsonschema (solo validación de desarrollo).

**Spec:** `docs/specs/poliquetos-asesinos-v2.md`, secciones 4, 13 y 15.

## Global Constraints

- Una fase por entrega, un commit por fase; no implementar todo de una vez.
- Conservar el motor y el stack actual.
- Mantener ambas ediciones HTML; no cambiar canciones según la indicación directa previa del usuario.
- El inventario describe el legado; no confundir sus estadísticas ni sus sprites procedurales con los nuevos assets.
- Los valores futuros de balance estarán en JSON. Los ejemplos del anexo son formatos, no sustitutos de las tablas de balance.

## Review Focus

- Enemigos compartidos: registrar todos sus mundos y roles sin duplicar su identidad.
- Jefes múltiples: conservar cada participante, incluidos los que comparten tipo base.
- Laboratorio: registrar los seis robots y los siete participantes actuales; diferenciar las propuestas v2.
- Repetibilidad: regenerar el inventario no debe producir diferencias si el HTML no cambió.
- Contratos: rechazar vidas negativas, IDs inválidos, atlas fuera de sus límites y oleadas de mundo incorrecto.
